# 岸基节点 / 港口端

ESP32 + 北斗 + LoRa + SYN6288 语音 + SSD1306 OLED + VL53L1X 激光测距。

一块板子做四件事：读北斗作为**岸端参考基准**、用 LoRa 收信标并在岸端告警、
和船端双向交换位置、把这些数据发布到网页上。

> **本版本已升级到三端统一的新协议**（带设备编号），
> 能和当前的船端 `beidou_gps_test`、信标 `C3_Coord_Sender` 直接互通。

## 一、和旧版的区别

旧版是按**没有设备编号的老协议**写的（信标发 `M,<序号>,…`、船端发 `V,<序号>,…`），
和现在的船端/信标对不上，三端实际不通。这一版做了三处改动：

| 改动 | 说明 |
| --- | --- |
| **协议加设备编号** | 新老两种格式都认，旧固件也能接进来 |
| **岸基广播改用 `R` 前缀** | 旧版用 `S`，和船端的 `S`（本船广播）撞车。`R` = Reference（参考站） |
| **信标按编号分槽位** | 最多同时跟踪 `MAX_BEACONS`（默认 4）只，多只信标不会互相覆盖 |

顺带修了一个隐患：旧版的重传识别只分“信标/船端”两类，
多只信标交替发会被误判成重传；现在按**发送者编号**分开记。

## 二、协议（三端一致）

前缀区分角色，**第 2 个字段统一是发送者编号**：

```
信标 -> 所有： M,<信标ID>,<序号>,P,<定位有效 0/1>,<纬度>,<经度>
船端 -> 所有： S,<船ID>,<序号>,P,<定位有效 0/1>,<纬度>,<经度>,
                 <对地速度节>,<航向度>,<卫星数>
本节点-> 所有：R,<岸基ID>,<序号>,P,<本节点定位有效 0/1>,<纬度>,<经度>
应答 -> 对方： A,<自己ID>,<序号>,C,<自己定位有效 0/1>,<纬度>,<经度>
```

**设备编号分配**（三端必须各不相同，在各自的 `config.h` 里设）：

| 设备 | 编号 |
| --- | --- |
| 船端 | `1` |
| 信标 | `11` / `12` / `13` … |
| 岸基 | `21` / `22` … |

**老格式也认**（第 2 个字段直接是序号，没有编号）：

```
M,<序号>,P,…        S,<序号>,P,…        A,<序号>,C,…
```

判断办法：**第 3 个字段**直接以 `P` 或 `C` 开头就是老格式。
不能用“第 2 个字段是不是数字”来判断 —— 两种格式那里都是数字。
这样旧固件的船端/信标也能接进来，不用三端同时换固件。

射频参数三端必须完全相同：`433MHz / SF10 / BW125kHz / 同步字 0x12 / 开启 CRC`。

## 三、接线

**与船端完全相同**，两端可以直接对测。

| 模块 | 模块引脚 | ESP32 |
| --- | --- | --- |
| **北斗** ATGM336H-5N | 5V / GND | 5V / GND |
| | TX | **GPIO17** |
| | RX | **GPIO18**（9600） |
| **LoRa** SX1278 | VCC / GND | 3.3V / GND |
| | SCK / MISO / MOSI | **GPIO14 / 19 / 23** |
| | NSS / RST | **GPIO13 / 27** |
| | DIO0 | **不接**（程序用轮询） |
| **语音** SYN6288 | VCC / GND | 5V / GND |
| | RXD | **GPIO16**（必接） |
| | TXD | **GPIO4**（可选） |
| | SPK± | 喇叭 8Ω |
| **OLED + 激光** | VCC / GND | 3.3V / GND |
| | SDA / SCL | **GPIO21 / 22** |

OLED 地址 0x3C，激光地址 0x29，挂在同一条 I2C 上不冲突。

接 ESP32 时，北斗模块上的 USB 口不要同时插电脑，两者是同一路串口。
北斗天线要拧到 SMA 口上，放在露天、平面朝天，远离金属。

## 五、网页

地址 **http://192.168.31.201**，四个页签：

| 页签 | 内容 |
| --- | --- |
| ① 本节点定位 | 定位、经纬度、卫星数、HDOP、时间、天线、LoRa、信道底噪、OLED、岸侧测距 |
| ② 落水信标 | 链路、定位、**编号**、**在线信标数**、序号、坐标、距信标、方位、RSSI/SNR，<br>外加**信标列表表格**和**确认告警按钮** |
| ③ 船端 | 链路、定位、序号、坐标、距船端、方位、RSSI/SNR |
| ④ 原始数据 | 位姿帧（0x01）、原始 GGA、地图链接 |

接口 `GET /data` 返回 JSON：本节点字段是裸名，信标前缀 `b`，船端前缀 `v`。
`GET /ack` 用于确认告警。

### 三个和"能不能真用"有关的设计

**一、顶部横幅"信标在线就报警"，不等定位有效。**

信标刚落水时北斗还没定上位（冷启动要 30~60 秒），那半分钟恰恰是最该让人
知道的时刻。所以横幅的判定是 `d.bLink`（在线），不是 `d.bLink && d.bValid`，
定位没拿到时文案会写"定位尚未获取，正在搜星"。

多只信标同时在线时，横幅还会带上"（共 N 只在线）"。

**二、② 页有一张信标列表。**

后端 `track` 支持最多 `MAX_BEACONS`（默认 4）只信标，每只按编号占一个槽位。
网页用一张表把每一只都列出来（编号 / 链路 / 定位 / 坐标 / 距岸基 / 方位 / RSSI），
三只同时落水时各占一行，不会只看到最后发信号的那一只。

JSON 里对应 `bs` 数组；`b*` 那一组仍然只描述"最近活跃的那只"，兼容旧代码。

**三、② 页有一个「确认告警」按钮。**

点了之后停止重复语音播报（落水、失联、恢复都不再念），但网页和屏上的显示照旧。
**等有新信标上线（从离线变在线）会自动解除确认，重新允许播报** ——
免得值班员确认过一次之后，后面真的又出事就不响了。

JSON 字段 `acked` 表示当前是否已确认。

**四、③ 页显示船端的对地速度 / 航向 / 卫星数。**

船端的 S 帧在这几个字段上是**多带的**：

```
S,<船ID>,<序号>,P,<有效>,<纬度>,<经度>,<对地速度节>,<航向度>,<卫星数>
```

信标帧只到经度为止。所以解析时一次把六个字段都试着读出来，读够几个算几个
（信标读到 3 个，船端读到 6 个），读到 6 个才填进 `hasExtra`。
这样以后协议再加字段也不会把这一端弄坏。

值班室靠这三个数判断：船在航还是在停泊、朝哪个方向开、定位可不可靠。

**五、每处都显示「最近更新 N 秒前」。**

光看"在线/离线"不知道数据有多新鲜 —— 是 1 秒前收到的，还是 14 秒前收到的？
特别是显示"离线"的时候，值班员没法判断是刚断还是断了很久。

现在 ②③ 页各有一张"最近更新"卡片，信标列表里也有一列。超过一分钟显示"X 分前"，
超过一小时显示"X 时前"，从来没收到过显示"未收到"。

串口/网页对应的 JSON 字段：`bAge`、`vAge`、`bs[].age`（单位秒，-1 = 从未收到）。

## 七、三端联动现状

| 场景 | 岸基节点 | 船端 | 信标 |
| --- | --- | --- | --- |
| 信标落水 | 收 M 帧、回 ACK、网页告警、语音播报 | 收 M 帧、语音/蜂鸣器告警 | 发 M 帧 |
| 正常值守 | 每 2 秒发 R 帧 | **暂不解析 R 帧**（见下） | — |
| 船端在航 | 收 S 帧，显示“距船端/方位” | 每 2 秒发 S 帧 | — |
| 信标失联 | 15 秒收不到 M 帧判离线并播报 | 同样判离线 | — |
| 船端失联 | 15 秒收不到 S 帧判离线（不播报） | — | — |

### 有一处还没打通

**船端现在不解析岸基的 R 帧**（它只认 `M,` 开头的信标帧），
所以船端**不会显示“距岸基 / 岸基方位”**。

要打通这一段，得在船端加一个“岸基跟踪”的模块（和信标跟踪类似，
解析 `R` 帧、算距离方位、上屏/上网）。**岸基这边不用再改。**

## 八、烧录

1. 开发板选 **ESP32 Dev Module**
2. 端口选对应串口，点上传（失败时按住 BOOT 再上传）
3. 程序空间不够就把 **工具 → Partition Scheme** 改成
   `Huge APP (3MB No OTA/1MB SPIFFS)`

用到的库：`LoRa` 0.8.0、`U8g2`、`VL53L1X`（作者 pololu）；
`WiFi` / `WebServer` / `SPI` / `Wire` 由 ESP32 支持包自带。

## 九、常见问题

| 现象 | 怎么查 |
| --- | --- |
| 收到 `无法解析的包：S,…` | 对方的帧格式没对上，确认三端都是新协议 |
| 收不到信标 | 信标没上电、不在距离内，或者射频参数不一致 |
| 网页打不开 | 先看串口打印的 IP（**以串口为准**），确认电脑连的是 2.4GHz |
| 信标编号显示“老格式” | 信标还在跑旧固件，重烧成带编号的版本 |
| 屏不亮 | I2C 版接法：VCC→3.3V、GND、SDA→21、SCL→22；确认装了 U8g2 |
| 测距一直无效 | 先看开机 I2C 扫描有没有 0x29；目标别太近（<4cm）或太远（>4m） |
