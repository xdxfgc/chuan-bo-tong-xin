# 船舶终端（ESP32 + 北斗 + 激光测距 + LoRa 信标接收 + 语音播报）

一块板子做四件事：读北斗定位、读激光测距、用 LoRa 收信标坐标、用语音把落水信标的方向和距离喊出来，
同时把这些数据发布到网页上。

## 一、代码结构

程序按功能拆成模块，每个模块一对 `.h` / `.cpp`，配置集中在 `config.h`。
以后新增硬件，照 `tof.h` / `tof.cpp` 的写法再加一对文件，
然后在主程序 `setup()` 里加一行 `xxxBegin()`、在 `loop()` 里加一行 `xxxUpdate()` 即可。

| 文件 | 作用 |
| --- | --- |
| `beidou_gps_test.ino` | 主程序：初始化各模块并调度 |
| `config.h` | 全部引脚、WiFi、射频、播报节奏等参数 |
| `gb2312_voice.h` | SYN6288 播报用的 GB2312 词表 |
| `gnss.h` / `gnss.cpp` | 北斗定位：NMEA 解析、0x01 位姿帧、定位失锁告警 |
| `tof.h` / `tof.cpp` | 激光测距 VL53L1X |
| `oled.h` / `oled.cpp` | OLED 显示（SSD1306 128x64，与激光共用 I2C） |
| `imu.h` / `imu.cpp` | MPU6050 六轴姿态（同样挂在 I2C 总线上） |
| `mag.h` / `mag.cpp` | 磁力计 GY-282（HMC5983）：航向、标定、I2C 自恢复，走**独立的 Wire1** |
| `berth.h` / `berth.cpp` | 靠泊辅助：距离滤波、接近速度拟合、分级告警、靠妥判定 |
| `button.h` / `button.cpp` | 板载 BOOT 键：短按设出发点，长按开始标定 |
| `cmd.h` / `cmd.cpp` | 串口命令：音量、标定、出发点、磁偏角、扫描 |
| `lora_link.h` / `lora_link.cpp` | LoRa 收发与 ACK 应答 |
| `voice.h` / `voice.cpp` | SYN6288 语音播报与在线调音量 |
| `beacon.h` / `beacon.cpp` | 信标接收、方位解算、搜索引导、播报节流 |
| `net.h` / `net.cpp` | WiFi 与网页服务（页面 + JSON 接口） |

依赖方向是单向的：`config` 在最底层；`beacon` 用到 `gnss`/`lora`/`voice`；
`net` 用到 `gnss`/`tof`/`beacon`；主程序把它们串起来。

注意：LoRa 模块的文件名是 `lora_link.*`，不能叫 `lora.*`。Windows 不区分文件名大小写，
如果叫 `lora.h`，`#include <LoRa.h>`（库头文件）会优先匹配到同目录的这个文件，
导致库加载失败、编译时报 `'LoRa' was not declared`。

## 二、接线

北斗定位模块 ATGM336H-5N：

| 模块引脚 | ESP32 | 说明 |
| --- | --- | --- |
| 5V | 5V | 供电 |
| GND | GND | 必须共地 |
| TX | GPIO17 | 模块发数据，接 ESP32 接收脚 |
| RX | GPIO18 | ESP32 发数据，接模块接收脚 |

激光测距模块 VL53L1X（I2C）：

| 模块引脚 | ESP32 | 说明 |
| --- | --- | --- |
| VIN | 3.3V | 只能接 3.3V，接 5V 会烧坏 |
| GND | GND | 必须共地 |
| SCL | GPIO22 | I2C 时钟 |
| SDA | GPIO21 | I2C 数据 |
| GPIO1 / XSHUT | 空着 | 可以不接 |

OLED 显示屏 SSD1306（I2C，和激光共用同一条总线）：

| 模块引脚 | ESP32 | 说明 |
| --- | --- | --- |
| VCC | 3.3V | 供电 |
| GND | GND | 共地 |
| SDA | GPIO21 | 和激光共用 |
| SCL | GPIO22 | 和激光共用 |
| 地址 | 0x3C | 少数模块是 0x3D，读不出就改 config.h |

MPU6050 六轴姿态（I2C，同样挂在这条总线上）：

| 模块引脚 | ESP32 | 说明 |
| --- | --- | --- |
| VCC | 3.3V | 供电 |
| GND | GND | 共地 |
| SDA | GPIO21 | 和激光、OLED 共用 |
| SCL | GPIO22 | 和激光、OLED 共用 |
| AD0 / ADO | GND 或不接 | 地址 0x68；接高电平变 0x69 |
| INT / XDA / XCL | 不接 | 暂时用不上 |

磁力计 GY-282 / HMC5983（**单独一路 I2C，不和其他模块共用**）：

| 模块引脚 | ESP32 | 说明 |
| --- | --- | --- |
| VCC | **3.3V** | 不能接 5V：上拉电阻会跟着抬到 5V，超出 ESP32 的 IO 耐压 |
| GND | GND | 共地 |
| SDA | **GPIO25** | 走 Wire1 |
| SCL | **GPIO26** | 走 Wire1 |

两条 I2C 总线是分开的：**Wire**（GPIO21/22）挂激光 0x29、OLED 0x3C、MPU6050 0x68；
**Wire1**（GPIO25/26）只挂磁力计 0x1E。分开的原因是磁力计代码里带自动降速和总线复位，
和激光共用一条线时，它一折腾会连带影响每 50 毫秒就要读一次的激光测距。
想省一对脚的话，把 `config.h` 里的 `I2C_BUS_INDEX` 改成 0、`I2C_SDA`/`I2C_SCL` 改成 21/22 即可。

I2C 是总线，多个器件共用同样两根线靠地址区分：**激光 0x29、OLED 0x3C、MPU6050 0x68**，
三个地址互不冲突，挂在一起没问题。

⚠ MPU6050 里没有磁力计：俯仰角和横滚角很准，但偏航角（船头朝向）会随时间漂移。
要做到"信标在左前方"这种相对船头的播报，还需要再加一片三轴磁力计（文档里配的是 QMC5883L，
地址 0x0D，同样可以挂在这条总线上）。

LoRa 模块 SX1278（Ra-01 / Ra-02，433MHz，SPI）：

| 模块引脚 | ESP32 | 说明 |
| --- | --- | --- |
| VCC | 3.3V | 只能 3.3V |
| GND | GND | 共地 |
| SCK | GPIO14 | SPI 时钟 |
| MISO | GPIO12 | SPI 数据入 |
| MOSI | GPIO13 | SPI 数据出 |
| NSS | GPIO27 | 片选 |
| RST | GPIO32 | 复位 |
| DIO0 | 不接 | 程序用轮询，不需要中断脚 |

SYN6288 语音模块：

| 模块引脚 | ESP32 | 说明 |
| --- | --- | --- |
| RXD | GPIO16 | 必接，ESP32 发、模块收 |
| TXD | GPIO4 | 可选，接上能看到模块应答 0x41 |
| VCC | 5V | 功放吃电流，5V 声音才够大 |
| GND | GND | 共地 |
| SPK+ / SPK- | 喇叭 | 接小喇叭 |

接 ESP32 时，北斗模块上的 USB 口不要同时插到电脑，两者是同一路串口，会冲突。
北斗天线要拧到 SMA 口上，放在露天、平面朝天，远离金属。

## 三、WiFi 配置

相关设置都在 `config.h` 里。当前用固定 IP，网页地址固定为 **http://192.168.31.200**。

| 项目 | 值 |
| --- | --- |
| SSID | Xiaomi_AE4D |
| 密码 | 123456780 |
| 网段 | 192.168.31.x |

小米路由器有两个 WiFi 名字：**不带 `_5G` 的是 2.4GHz，带 `_5G` 的是 5GHz**。
ESP32 只支持 2.4GHz，必须用 `Xiaomi_AE4D`。

固定 IP 连不上会自动回退成路由器自动分配；再连不上就开热点兜底：
热点名 `Beidou-GPS`、密码 `12345678`、网页地址 http://192.168.4.1。

## 四、LoRa 通信协议

和信标端（ESP32-C3）约定好的文本协议，两边必须一致：

```
信标 → 本板：  M,<序号>,P,<定位有效 0/1>,<纬度>,<经度>
本板 → 信标：  A,<序号>,C,<本方定位有效 0/1>,<纬度>,<经度>
```

信标每 2 秒发一次，本板收到立刻回 ACK，信标靠它判断这一轮成功。
同一序号重复到达只回 ACK，不重复播报。
射频参数两端必须完全相同：`433MHz / SF10 / BW125kHz / 同步字 0x12 / 开启 CRC`。

## 五、语音播报

SYN6288 只认 GB2312，不能直接发 UTF-8 中文，所以 `gb2312_voice.h` 里把要用到的词
预先算成字节，数字和 `[v16]` 音量标记在运行时拼上去。

播报内容形如："人员落水，信标在东北方向，距离约 123 米，坐标北纬 26.2091 度，东经 111.5989 度。"

为避免语音排队，做了节流：两次播报最短间隔 8 秒；目标移动超过 3 米、方位变化、
或超过 20 秒，才重新播报。链路中断超过 15 秒播报"与信标失去联系"，恢复时播报"通信已恢复"。

方位播报会优先使用**相对船头**的八个方位（正前方、右前方……左前方），前提是磁力计在位**并且已经标定**；
没标定或者磁力计掉线时，自动退回"信标在东北方向"这样的绝对方位，避免给出错误指引。

## 六、串口命令

串口监视器波特率 **115200**，行尾选「换行」或「NL & CR」。输入 `help` 可以看全部命令：

| 命令 | 作用 |
| --- | --- |
| `v0` ~ `v16` | 语音音量（会播一句"你好"试听） |
| `cal [秒]` | 开始磁力计标定，默认 15 秒（拿起来绕「8」字慢慢转） |
| `cal stop` | 提前结束标定 |
| `cal reset` | 清除已保存的标定 |
| `zero` | 把当前船头朝向设为出发点（0°） |
| `decl -5.2` | 设置磁偏角（真北修正），长沙一带约 -5 |
| `mag` | 立刻打印一行磁力计数据 |
| `dock` | 打印靠泊状态（距离、接近速度、告警） |
| `scan` | 扫描磁力计所在的 I2C 总线，正常应看到 0x1E |

## 七、板载按键

ESP32 开发板上的 **BOOT 键**（GPIO0）可以直接操作，不用开电脑：

| 动作 | 效果 |
| --- | --- |
| 短按 | 把当前船头朝向设为出发点（0°） |
| 长按 3 秒 | 开始磁力计标定 |
| 标定中短按 | 提前结束标定，用已转到数据算结果 |

不想用就把 `config.h` 里的 `BTN_ENABLE` 改成 0。

## 八、靠泊辅助

只用激光测距，不需要额外硬件。**靠近到 3.5 米自动开始监测**，离开到 3.8 米（滞回 0.3 米）
并持续 3 秒后自动结束。

处理链是：原始距离先做 3 点中值去野值，再做 8 点滑动平均；然后用 0.4 秒窗口做最小二乘拟合
求接近速度。这两步是必须的——激光噪声约 ±5 毫米，直接拿相邻两帧求差算速度，误差有 0.1 m/s，
而提醒阈值才 0.15 m/s，噪声就能把告警刷满。

判断规则按文档附录 B：

| 告警码 | 条件 | 等级 | 播报 |
| --- | --- | --- | --- |
| 0x01 | 接近速度 > 0.15 m/s | 提醒级 | 靠泊速度偏大，请减速 |
| 0x02 | 接近速度 > 0.30 m/s | 严重级 | 靠泊速度过大，立即停船 |
| 0x03 | 距岸 < 0.5 米且速度 > 0.10 m/s | 严重级 | 距岸过近，请停船 |

告警带 3 帧去抖，避免在阈值附近反复跳。

**距离播报**按档位给，越近播得越勤：

| 距离 | 播报 | 间隔 |
| --- | --- | --- |
| 3.5 ~ 2.0 米 | 距离三米二 | 2.5 秒 |
| 2.0 ~ 1.0 米 | 距离一米八 | 2.0 秒 |
| 1.0 ~ 0.5 米 | 距离八十厘米 | 2.0 秒 |
| 0.5 米以内 | 距离三十厘米，即将靠妥 | 2.0 秒 |

告警优先级高于距离播报，触发时先念告警。观察窗内距离变化小于 5 厘米时自动静默，不会反复念
同一个数字。

**靠妥判定**看的是"停下来"而不是"有多近"：速度小于 0.03 m/s、观察窗内变化小于 3 厘米、
且距离小于 1 米，三条同时满足就播报"靠泊完成"。这样护舷厚薄都不影响判定。另外，激光量程下限
是 4 厘米，如果刚才还贴着、读数突然失效，也判为已接触。

阈值全在 `config.h` 里，实测觉得太敏感或太迟钝直接改。

## 九、在 Arduino IDE 中烧录

1. 安装 ESP32 支持包：开发板管理器搜索 `esp32`，装 Espressif Systems 的包。
2. 用 Arduino IDE 打开 `beidou_gps_test.ino`（其余文件会在同一窗口里一并打开）。
3. 开发板按实际硬件选 **ESP32 Dev Module** 或 **ESP32S3 Dev Module**（两种都已验证能编译）。
4. 端口选 ESP32 对应的串口，点上传。失败时按住板上 BOOT 键再上传。

用到的库都已装在这台电脑的 Arduino 库里：`VL53L1X` 1.3.1（Pololu）、`LoRa` 0.8.0（sandeepmistry）。
换电脑时在库管理器里各搜一个装上即可。

## 十、查看结果

串口监视器波特率 **115200**。每秒打印五块内容：北斗定位、激光距离、姿态（俯仰/横滚/温度）、
磁力计（航向/相对出发点/磁场强度/是否已标定）、信标链路状态（在线与否、RSSI、信标坐标、搜索引导）。

OLED 屏幕有三种画面，自动切换：**靠泊监测中优先显示靠泊画面**（大号距离数字 + 接近速度 + 告警等级），
其次是收到信标坐标时的信标画面，其余时候显示本船状态。靠泊优先是因为那是人在主动操作、需要盯着屏幕看。

下面两种是信标画面和本船状态画面（磁力计已标定，方向按相对船头显示）：

```
信标坐标              -95dBm       本船状态          13星 3D
N26.209136                         N26.209136
E111.598909                        E111.598909
左前方 123米           ↗            激光 1234mm  航向201
本船 26.2091 111.5989              俯仰 3.2  横滚 1.8
```

收到过信标坐标时显示左边那一屏，还没收到时显示右边的本船状态。
左边那屏箭头上方的小尖表示"屏幕上方就是船头"；磁力计没标定时箭头会退回指北，文字也变成"东北"这样的绝对方位。

靠泊画面的布局是：第一行"靠泊监测"加右侧的等级（正常/提醒/严重/已靠妥），中间一行大号距离数字
带单位，下面一行接近速度，最后一行是状态或告警文字。

网页地址 **http://192.168.31.200**，页面上有定位、激光、姿态、航向、靠泊、信标六组卡片。
靠泊那组显示距离、接近速度和状态；有靠泊告警时顶部横幅也会变红提示。
收到有效信标坐标时，顶部横幅变成红色落水提示，显示方向和距离。

## 十一、程序空间提醒

加上 OLED 的中文字库、Adafruit 库、磁力计和靠泊模块之后，程序占用已经到 **97%**，余量只剩 30 多 KB。
如果以后还要加功能导致编译报"程序空间不足"，最省事的办法是在 Arduino IDE 里把
**工具 → Partition Scheme 改成 Huge APP (3MB No OTA/1MB SPIFFS)**，程序可用空间会从
1.3MB 变成 3MB，不用改任何代码。

## 十二、常见问题

- LoRa 初始化失败：检查 3.3V 供电和 SPI 五根线，确认模块是 Ra-01/Ra-02 的 433MHz 版本。
- 收不到信标：确认信标端的频率/SF/带宽/同步字和本板完全一致，天线接好。
- 语音不响：确认模块供电 5V、喇叭接在 SPK+/SPK-、GPIO16 接模块 RXD。
- 网页打不开：确认手机或电脑和 ESP32 在同一网络，地址用 `http://` 开头。
- 串口没有定位输出：检查 TX/RX 是否接反、天线是否接好、波特率是否为 9600。
