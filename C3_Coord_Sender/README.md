# 船舶信标（坐标发送端）

ESP32-C3 SuperMini + SX1278 433MHz。每 2 秒向船端和岸基广播自己的坐标，
收到应答才算这一轮成功，收不到自动重发（最多 3 次）。

## 这次相对原版的改动

**一、加了本机标识。** 发送帧从 `M,<序号>,P,...` 改成
`M,<信标ID>,<序号>,P,<定位有效>,<纬度>,<经度>`。

`DEV_ID` 在 `C3_Coord_Sender/config.h` 里，第一只信标用 **11**，第二只 12，第三只 13。
船端和岸基靠这个数字区分"这一帧是谁发的"——多只信标同时工作时才不会混在一起。
（船端自己的 ID 是 1，所以数字上一眼能看出是船还是信标。）

**二、应答解析改成兼容两种格式。** 船端的应答现在带着自己的 ID
（`A,<船ID>,<序号>,C,<本船定位有效>,<纬度>,<经度>`），旧版是不带 ID 的。
代码统一从 `,C,` 往后取字段，**新老两种格式都能解析**，所以船端不管哪个版本都能配合。

## 接线（ESP32-C3 SuperMini + SX1278）

| SX1278 引脚 | ESP32-C3 |
| --- | --- |
| VCC | 3.3V |
| GND | GND |
| SCK | **GPIO6** |
| MISO | **GPIO2** |
| MOSI | **GPIO7** |
| NSS | **GPIO10** |
| RST | **GPIO8** |
| DIO0 | **不接** |

⚠ **DIO0 千万别接**：那个位置是 GPIO9，是启动模式脚，接上之后芯片复位就进下载模式，程序不跑。
本程序用轮询读中断标志，不需要 DIO0。

天线一定要接上。

## 射频参数（必须与船端完全一致）

```
频率    433 MHz
扩频因子 SF10
带宽     125 kHz
同步字   0x12
CRC      开启
```

这五项只要有一项不一样，两边就互相收不到。

## 开发板与串口

Arduino IDE 里开发板选 **ESP32C3 Dev Module**（SuperMini 也选它），串口监视器 **115200**。

⚠ **开发板一定要选 `ESP32C3 Dev Module`**，不能选 `ESP32 Dev Module`。
后者指的是普通 ESP32（Xtensa 双核），而 C3 是 RISC-V 单核，机器码不一样，
就算编过了 esptool 也会因为芯片型号对不上拒绝烧录。
选错板子时典型报错是 `'USBCDC' does not name a type`——那是普通 ESP32 没有
USB CDC 这一类导致的。

程序里已经处理了 USB CDC 的兼容问题，不用动 IDE 那个"USB CDC On Boot"的设置；
`debug.h` 里做了兜底，万一板子选错也只是打印通道不对，不会整个编不过。

## 代码结构（模块化）

每个功能一对 `.h` / `.cpp`，主程序只留"初始化 + 调度"。以后加功能，
再新建一对文件，然后在 `setup()` / `loop()` 里各加一行就行，不用动其它模块。

| 文件 | 管什么 |
| --- | --- |
| `C3_Coord_Sender.ino` | 主程序：初始化、每轮取坐标 → 组帧 → 发 → 等应答 |
| `config.h` | **所有可调参数**：引脚、射频、节奏、`DEV_ID`、`SRC_MODE` |
| `debug.h` / `debug.cpp` | 调试串口（兼容 C3 的两种 USB 模式） |
| `coord.h` / `coord.cpp` | 坐标来源（固定 / 绕点 / 本端北斗 / 串口输入） |
| `radio.h` / `radio.cpp` | LoRa 收发底层：发一帧、收一帧 |
| `link.h` / `link.cpp` | 一问一答：等应答、重传、统计成功/重发/失败 |
| `water.h` / `water.cpp` | 水感检测（落水触发）：电极 / 杜邦线 / 串口命令 |

各模块的对外接口：

```
coord :  coordBegin()  coordPoll()  coordGet()  coordBuildPayload()
radio :  radioBegin()  radioIsReady()  radioSend()  radioReceive()
link  :  linkSendWithAck()  linkPrintStats()
```

**换接线、改参数只动 `config.h`。** 引脚、射频、节奏、`DEV_ID`、坐标来源全在里面。

`DEV_ID` 和 `SRC_MODE` 外面包了 `#ifndef`，所以既能在 `config.h` 里改，
也能在编译时用 `-DDEV_ID=12` 覆盖。

## 坐标从哪来（SRC_MODE）

| 模式 | 来源 | 用途 |
| --- | --- | --- |
| **0** | 固定坐标 | 联调最省事，烧完就有数据（默认） |
| 1 | 绕固定点缓慢转圈 | 演示用，能看方向和距离一直在变 |
| 2 | 接北斗模块，用真实定位 | 正式使用 |
| 3 | 串口手动输入坐标 | 不用重烧就能改目标点 |

**模式 3 特别适合调试**：在串口监视器里敲 `纬度,经度` 回车，比如

```
26.210000,111.600000
```

从下一轮开始就按这个坐标发出去。这样你可以手动"模拟信标在移动"，看船端的方位和距离跟着变，
不用真的拿两只信标跑来跑去。

### 模式 2：接北斗模块

| 北斗模块 | ESP32-C3 | 说明 |
| --- | --- | --- |
| TXD | **GPIO20** | 模块发数据 → C3 收 |
| RXD | **GPIO21** | C3 发数据 → 模块收 |
| VCC | 3V3 | 看模块标注 |
| GND | GND | 必须共地 |
| PPS | 不接 | 程序用不到秒脉冲 |

**要交叉接**：模块 TXD 接 C3 的接收脚，模块 RXD 接 C3 的发送脚。接反了收不到任何数据，
这是最常见的错误。波特率 9600，ATGM336H-5N 出厂默认就是这个，不用改。

GPIO20/21 在 C3 上虽然是 UART0 的默认脚，但核心库在 C3 上不会初始化 UART0
（C3 固定为原生 USB 模式），所以这两个脚是空闲的，可以放心用。

接好线之后把 `SRC_MODE` 改成 **2**，重新烧录。开机串口会打印：

```
本端北斗：UART1 RX=GPIO20 TX=GPIO21  9600 bps
          模块 TXD -> 上面的 RX 脚，模块 RXD -> 上面的 TX 脚（要交叉）
          冷启动第一次定位要 30~60 秒，室内基本定不上，把天线贴窗边或拿出去
```

之后每 5 秒会打一行状态，把三种情况分开：

| 串口打印 | 说明 |
| --- | --- |
| `一句数据都没收到` | 接线/波特率/供电不对，先查 TX、RX 有没有接反 |
| `串口断了，之前有数据现在没有` | 线松了 |
| `正在搜星…（卫星 N）` | 正常，还没定上位，把天线挪到窗边或室外 |
| `已定位  卫星 N  纬度, 经度` | 正常工作了 |

定位超过 10 秒没有更新会自动置为无效（`GNSS_STALE_MS`），避免模块被拔掉之后
还拿着过期坐标一直往外发。

## 水感检测（落水触发）

信标平时应该是**睡着的**，入水才醒过来上报。水感检测就负责"醒过来"这件事。

### 硬件：两片不锈钢电极，不用任何电阻电容

```
     ESP32-C3                   不锈钢电极
   ┌──────────┐                ┌──────┐
   │   GPIO3  ├────────────────┤ 片 A │
   │          │                └──────┘
   │          │                  ⚡ 间距 3~5 毫米
   │          │                ┌──────┐
   │   GPIO4  ├────────────────┤ 片 B │
   └──────────┘                └──────┘
```

电极必须是**不锈钢**（铜会发绿、铁会锈穿）。每片接触面积 1cm² 以上，
间距 3~5 毫米。最省事的做法是拧两枚 M3 不锈钢螺丝在一块塑料板上，间距 4 毫米，
背面用热熔胶封住，只让螺丝头露出来。

### 为什么要间歇通电

平时两个脚都是**高阻输入**，电极上一滴电都没有——零功耗、不腐蚀。
每 500 毫秒采样一次，每次两个方向各测一遍（A 输出低 B 读，然后 B 输出低 A 读），
**电流方向交替**。电极长期带着直流电泡在水里会电解腐蚀，几天就烂了，
文档表 18 专门写了这件事。

### 临时测试不用做电极

两根杜邦线分别插 GPIO3 和 GPIO4，**把两个线头碰在一起就是"入水"**，
分开就是"出水"。走的电路和真电极完全一样，以后换真电极代码一行都不用改。

也可以用串口命令（`WATER_SIM_CMD = 1` 时）：

```
wet on     强制置为"入水"（演示用，不用碰硬件）
wet off    解除强制，恢复真实采样
wet        打印当前状态
```

串口上会看到：

```
[水感] 检测到入水
[水感] 已离水
```

注意：`SRC_MODE = 3`（串口输入坐标）也要读串口，和 `WATER_SIM_CMD` 不能同时开。

### 只在入水后才上报（SEND_ONLY_WET）

| 值 | 行为 |
| --- | --- |
| `0` | 不管有没有入水都照常每 2 秒上报（默认，联调用） |
| `1` | 平时静默，入水才开始上报（真正信标的行为，演示用） |

改成 1 之后的演示流程：

```
1. 信标上电 —— 串口打印"未入水，保持静默"，什么都不发
   船端：信标链路 离线
2. 把两根杜邦线碰在一起并持续 2 秒（或敲 wet on）
   串口打印"[信标] 确认落水（连续湿 2.0 秒），开始上报"
   船端：链路在线 → 落水告警 → 语音播报 → 蜂鸣器响 → 网页弹告警
3. 把线分开（或敲 wet off）
   串口打印"[信标] 已离水，恢复静默"，信标停止上报
   船端 15 秒后播报"与信标失去联系"
```

**第 2 步为什么要"持续 2 秒"**：这是三重确认里的**持续时间**那一条。
光碰到水不算，要连续湿够 `WATER_CONFIRM_MS`（默认 2000 毫秒）才认为真落水。
这样线头抖一下、浪溅一下都不会触发。实际上因为采样间隔是 500 毫秒，
从碰水到开始上报大约是 2~2.5 秒，仍在文档要求的 3 秒以内。

短暂碰一下线头（不到 2 秒）会看到水感打印"[水感] 检测到入水"和"[水感] 已离水"，
但**信标不会开始上报** —— 这就是持续时间在起作用。

### 相关参数（config.h）

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `WATER_PIN_A` / `WATER_PIN_B` | 3 / 4 | 电极引脚，只能从 GPIO0/1/3/4/5 里挑 |
| `WATER_SAMPLE_MS` | 500 | 采样间隔，越小越灵敏、越大越省电 |
| `WATER_CONFIRM_MS` | 2000 | 连续湿多久才算真落水（三重确认的"持续时间"） |
| `WATER_SIM_CMD` | 1 | 是否开放 `wet` 串口命令 |
| `SEND_ONLY_WET` | 0 | 是否只在入水后才上报 |

## 姿态判定（MPU6050）—— 三重确认的第二条

三重确认里，水感是**主触发**，姿态是**抑制误报**：分辨"在船上被雨淋/上浪"
和"真的漂在水里"。人在船上被淋，姿态是不会变的。

### 接线

| MPU6050 模块 | ESP32-C3 | 说明 |
| --- | --- | --- |
| 3V3 | **3V3** | ⚠ 只能 3.3V，接 5V 直接烧 |
| GND | GND | |
| SDA | **GPIO0** | |
| SCL | **GPIO1** | |
| A0 | **GND** | 接 GND 才是地址 0x68；悬空是 0x69 |
| INT | 不接 | |

**别照抄网上"SDA→GPIO21 / SCL→GPIO22"那种接法**——那是普通 ESP32 的。
C3 上 GPIO22 根本不存在，GPIO20/21 已经被北斗占用了。

### 它提供什么

| 信号 | 怎么来的 | 用途 |
| --- | --- | --- |
| 合加速度 | `√(ax²+ay²+az²)`，静止时 1.0 | 看"失重"和"入水冲击" |
| 姿态角 | 用重力分量算俯仰/横滚 | 看"站着"还是"躺平" |
| 运动强度 | 半秒窗口内合加速度的峰峰值 | 看"在动"还是"漂着" |

### 三条判据

```
姿态符合漂浮 = ① 有过"失重→冲击"的入水波形
             AND ② 相对上电基准转过 60° 以上
             AND ③ 入水后运动变平静
```

判据①最有辨别力：真落水会**先掉到 0.6g 以下（自由落体），再冲到 1.8g 以上
（砸进水里）**，这个组合被浪打到身上几乎不会出现。

判据②必须用**相对上电时的基准**，不能用绝对角度——救生衣的佩戴方向
每个人不一样，模块装的位置也不一样。

### 三条子判据怎么用（POSTURE_JUDGE）

| 值 | 行为 |
| --- | --- |
| **1（默认）** | 姿态参与三重确认 |
| 0 | 姿态不参与（只采集打印）——三重确认实际变成"水感 + 持续时间"两重，调传感器时用 |

### ⚠ 现在的阈值是"推算的首版值"，没做完标定

数据来源：**静止 / 走动 / 抖动**三组是**实测的**（2026-10-05），
但**漂浮那一组是推算的**（用波浪加速度 `a = 波幅 × ω²` 估算），没实测。

所以现在只保证"能用"。**报告里写"实测标定"之前必须补测漂浮数据。**

补测做法：**竖直拿着模块上电**（模拟穿在救生衣上站着），然后
装进食品保鲜袋放水盆里漂着，记二十秒。

### 实测数据（2026-10-05）

| 场景 | 合加速度 | 运动（半秒峰峰值） | 相对基准 |
| --- | --- | --- | --- |
| 静止 | 1.003 ~ 1.008 g | 0.013 ~ 0.040 g | 3.7 ~ 4.9° |
| 走动 | 0.983 ~ 1.105 g | 0.059 ~ 0.215 g | 24 ~ 51° |
| 抖动（模拟上浪） | 0.921 ~ **3.694 g** | **1.31 ~ 4.18 g** | 20 ~ 68° |
| 漂浮（**推算**） | 0.94 ~ 1.08 g | 0.05 ~ 0.20 g | 60 ~ 95° |

**两条关键结论：**

1. **光看"冲击"不行** —— 抖动就冲到了 3.69 g，超过冲击门槛。
   必须要求**先失重、再冲击**：抖动只有冲击（最低 0.921 g，没有失重），
   真落水才会先掉到 0.6 g 以下。这就是判据①的设计。
2. **摇摆频率改用频率而不是幅度** —— 实测手持晃动（0.115~0.182 g）和
   走动（0.059~0.215 g）**幅度完全重叠**，分不开；但走动是 1~2 Hz 步态，
   波浪只有 0.1~0.5 Hz，频率分得开。
   （不过频率要 8 秒窗口才算准，和"3 秒内激活"冲突，所以它**只打印、不判定**；
   激活判定用"平静度"就够——抖动是 1.3~4.2 g，落水后应该小得多。）

### 串口数据行

```
MPU6050 已就绪：地址 0x68  SDA=GPIO0  SCL=GPIO1  50Hz
          基准姿态：俯仰 12.3°  横滚 -45.6°
[姿态] 合加速度 1.002 g  俯仰   12.4°  横滚  -45.5°  相对基准   0.2°  运动 0.021 g  温度 28.4C
```

要是打出 `MPU6050 初始化失败！`，按它列的四条挨个查：3V3 有没有电、
GND 有没有共地、SDA/SCL 有没有接反、A0 有没有接 GND。

### 相关参数（config.h）

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `POSTURE_SDA_PIN` / `POSTURE_SCL_PIN` | 0 / 1 | I2C 引脚 |
| `POSTURE_ADDR` | 0x68 | A0 接 GND 是 0x68，悬空是 0x69 |
| `POSTURE_READ_MS` | 20 | 读取间隔（50Hz） |
| `POSTURE_FREEFALL_G` | 0.6 | 低于此值算失重 |
| `POSTURE_IMPACT_G` | 1.8 | 失重后再高于此值算入水冲击 |
| `POSTURE_TILT_MIN_DEG` | 55 | 判据②：相对基准倾角超过这个算"翻转过" |
| `POSTURE_CALM_MAX_G` | 0.30 | 判据③：运动小于这个算"平静" |
| `POSTURE_JUDGE` | 1 | 姿态是否参与三重确认 |

## 落水激活状态机（trigger）+ 复位按键（button）

三重确认不是"此刻满不满足"，而是一个**过程**，所以用状态机：

```
IDLE    平时
  ↓ 水感连续湿够 2 秒
WAIT    等姿态条件成立（最多等 15 秒，超时就算误触发）
  ↓ 三条子判据都满足
ACTIVE  落水已确认，一直保持
  ↓ 长按 BOOT 键 5 秒 / 串口敲 reset
IDLE
```

**"一直保持"很重要**：一旦确认激活，中途被浪盖住又露出来、或者短暂离水，
都不会退出。这是文档 6.3 的行为——打捞上来擦干，长按复位键五秒才退出。

### 复位按键

用板子上现成的 **BOOT 键（GPIO9）**，长按 5 秒复位，不用加硬件。

> ⚠ 上电时别按着 BOOT —— 按住 BOOT 上电，芯片会进下载模式，程序不跑。

### 串口命令

串口监视器 **115200**，行尾选「换行」：

| 命令 | 作用 |
| --- | --- |
| `help` | 打印命令清单 |
| `wet` | 看当前水感状态 |
| `wet on` / `wet off` | 强制"入水" / 解除（演示用，不用碰电极） |
| `post` | 看姿态三条判据的详情 |
| `sim post on` / `sim post off` | 强制姿态条件通过 / 解除 |
| `reset` | 复位激活状态（等同长按 BOOT 键 5 秒） |
| `trig` | 看激活状态 |

**为什么需要 `sim post`**：按键模拟不出"失重→冲击"的波形。
演示时如果条件不具备，可以用它把姿态这一条强制通过，
这样能演出完整的"三重确认"流程。真机上关掉就行。

### 串口长什么样

```
[水感] 没水（干燥）  两方向都不导通  累计采样 10 次
[姿态] 合加速度 1.002 g  俯仰 12.4°  横滚 -45.5°  相对基准 0.2°  运动 0.021 g  温度 28.4C  摇摆 0.24 Hz  [①无冲击 ②未翻转 ③平静]
[激活] 状态 待机            累计激活 0 次
```

落水确认的那一刻：

```
[水感] 检测到入水
[激活] 水感已确认，正在等姿态条件…
[姿态] ★检测到入水冲击（合加速度 2.14 g）
[激活] ★三重确认通过，落水已确认（第 1 次）—— 开始上报
[激活] 要退出请长按板载 BOOT 键 5 秒，或串口敲 reset
```

## 烧三只信标时怎么区分

改 `DEV_ID` 再烧下一只：

```
第一只： #define DEV_ID 11
第二只： #define DEV_ID 12
第三只： #define DEV_ID 13
```

船端收到之后，串口和网页上会显示是哪个编号的信标。

## 这个程序还不是完整的信标

它解决的是"**怎么发**"，还没解决"**什么时候该发**"和"**怎么省电**"。对照文档表 12，
还缺这些：

| 缺的 | 说明 |
| --- | --- |
| 水感触发 | 现在是一开机就不停地发；真正信标应该平时休眠、入水才醒 |
| 三重确认 | 水感 + 姿态 + 持续时间，文档的第二个创新点 |
| 姿态传感器 | 判断"是不是水面漂浮姿态"，抑制误触发 |
| 深度休眠 | 文档要求休眠电流 ≤200 µA、待机 ≥3 个月 |
| 电量监测 | 上报剩余电量（对应告警码 0x12） |
| 电池与浮体防水 | 硬件部分 |

所以现在它是**信标验证版**——能把射频链路、协议、重传都调通，
但还不能真的缝在救生衣上下水。
