# 船舶信标（坐标发送端）

ESP32-C3 SuperMini + SX1278 433MHz。每 2 秒向船端和岸基广播自己的坐标，
收到应答才算这一轮成功，收不到自动重发（最多 3 次）。

## 这次相对原版的改动

**一、加了本机标识。** 发送帧从 `M,<序号>,P,...` 改成
`M,<信标ID>,<序号>,P,<定位有效>,<纬度>,<经度>`。

`DEV_ID` 在 `C3_Coord_Sender/config.h` 里，第一只信标用 **11**，第二只 12，第三只 13。
船端和岸基靠这个数字区分"这一帧是谁发的"——多只信标同时工作时才不会混在一起。
（船端自己的 ID 是 1，所以数字上一眼能看出是船还是信标。）

**二、应答解析改成兼容两种格式。** 船端的应答现在带着自己的 ID
（`A,<船ID>,<序号>,C,<本船定位有效>,<纬度>,<经度>`），旧版是不带 ID 的。
代码统一从 `,C,` 往后取字段，**新老两种格式都能解析**，所以船端不管哪个版本都能配合。

## 接线（ESP32-C3 SuperMini + SX1278）

| SX1278 引脚 | ESP32-C3 |
| --- | --- |
| VCC | 3.3V |
| GND | GND |
| SCK | **GPIO6** |
| MISO | **GPIO2** |
| MOSI | **GPIO7** |
| NSS | **GPIO10** |
| RST | **GPIO8** |
| DIO0 | **不接** |

⚠ **DIO0 千万别接**：那个位置是 GPIO9，是启动模式脚，接上之后芯片复位就进下载模式，程序不跑。
本程序用轮询读中断标志，不需要 DIO0。

天线一定要接上。

## 射频参数（必须与船端完全一致）

```
频率    433 MHz
扩频因子 SF10
带宽     125 kHz
同步字   0x12
CRC      开启
```

这五项只要有一项不一样，两边就互相收不到。

## 开发板与串口

Arduino IDE 里开发板选 **ESP32C3 Dev Module**（SuperMini 也选它），串口监视器 **115200**。

程序里已经处理了 USB CDC 的兼容问题，不用动 IDE 那个"USB CDC On Boot"的设置。

## 代码结构（模块化）

每个功能一对 `.h` / `.cpp`，主程序只留"初始化 + 调度"。以后加功能，
再新建一对文件，然后在 `setup()` / `loop()` 里各加一行就行，不用动其它模块。

| 文件 | 管什么 |
| --- | --- |
| `C3_Coord_Sender.ino` | 主程序：初始化、每轮取坐标 → 组帧 → 发 → 等应答 |
| `config.h` | **所有可调参数**：引脚、射频、节奏、`DEV_ID`、`SRC_MODE` |
| `debug.h` / `debug.cpp` | 调试串口（兼容 C3 的两种 USB 模式） |
| `coord.h` / `coord.cpp` | 坐标来源（固定 / 绕点 / 本端北斗 / 串口输入） |
| `radio.h` / `radio.cpp` | LoRa 收发底层：发一帧、收一帧 |
| `link.h` / `link.cpp` | 一问一答：等应答、重传、统计成功/重发/失败 |

各模块的对外接口：

```
coord :  coordBegin()  coordPoll()  coordGet()  coordBuildPayload()
radio :  radioBegin()  radioIsReady()  radioSend()  radioReceive()
link  :  linkSendWithAck()  linkPrintStats()
```

**换接线、改参数只动 `config.h`。** 引脚、射频、节奏、`DEV_ID`、坐标来源全在里面。

`DEV_ID` 和 `SRC_MODE` 外面包了 `#ifndef`，所以既能在 `config.h` 里改，
也能在编译时用 `-DDEV_ID=12` 覆盖。

## 编译验证

以下是实际用 arduino-cli（esp32 core 3.3.10、LoRa 0.8.0）编译过的配置，全部通过：

| 配置 | 程序空间 | 内存 |
| --- | --- | --- |
| 默认（`SRC_MODE=0`） | 324296 / 1310720 字节（24%） | 14568 字节（4%） |
| `SRC_MODE=2` 本端北斗 | 335630 字节（25%） | 14816 字节（4%） |
| `SRC_MODE=3` 串口输入 | 325222 字节（24%） | 14624 字节（4%） |
| 默认 + USB CDC On Boot = Enabled | 324374 字节（24%） | 14568 字节（4%） |

余量很足，后面加水感触发、姿态判断、休眠都放得下。

## 坐标从哪来（SRC_MODE）

| 模式 | 来源 | 用途 |
| --- | --- | --- |
| **0** | 固定坐标 | 联调最省事，烧完就有数据（默认） |
| 1 | 绕固定点缓慢转圈 | 演示用，能看方向和距离一直在变 |
| 2 | 接北斗模块，用真实定位 | 正式使用 |
| 3 | 串口手动输入坐标 | 不用重烧就能改目标点 |

**模式 3 特别适合调试**：在串口监视器里敲 `纬度,经度` 回车，比如

```
26.210000,111.600000
```

从下一轮开始就按这个坐标发出去。这样你可以手动"模拟信标在移动"，看船端的方位和距离跟着变，
不用真的拿两只信标跑来跑去。

模式 2 的北斗接在 GPIO20（RX）/ GPIO21（TX），波特率 9600。

## 烧三只信标时怎么区分

改 `DEV_ID` 再烧下一只：

```
第一只： #define DEV_ID 11
第二只： #define DEV_ID 12
第三只： #define DEV_ID 13
```

船端收到之后，串口和网页上会显示是哪个编号的信标。

## 这个程序还不是完整的信标

它解决的是"**怎么发**"，还没解决"**什么时候该发**"和"**怎么省电**"。对照文档表 12，
还缺这些：

| 缺的 | 说明 |
| --- | --- |
| 水感触发 | 现在是一开机就不停地发；真正信标应该平时休眠、入水才醒 |
| 三重确认 | 水感 + 姿态 + 持续时间，文档的第二个创新点 |
| 姿态传感器 | 判断"是不是水面漂浮姿态"，抑制误触发 |
| 深度休眠 | 文档要求休眠电流 ≤200 µA、待机 ≥3 个月 |
| 电量监测 | 上报剩余电量（对应告警码 0x12） |
| 电池与浮体防水 | 硬件部分 |

所以现在它是**信标验证版**——能把射频链路、协议、重传都调通，
但还不能真的缝在救生衣上下水。
